uv

Environments, dependencies and lockfiles — the part everyone skips and everyone regrets skipping.

docs.astral.sh/uv

The problem uv solves

A typical Python project has used four tools to do one job.

venv

Creates an isolated environment. Knows nothing about your dependencies.

pip

Installs packages. Resolves them loosely and does not record what it actually installed.

pip-tools / poetry

Adds locking, slowly, with its own config format and its own opinions.

pyenv

Manages interpreter versions, separately again, with a separate install step.

uv is one binary that does all four, written in Rust, typically 10 to 100 times faster.

Module 1 — uv: environments and packaging

The pain point is reproducibility: "it works on my machine" is a dependency resolution problem 90 percent of the time.

What uv gives you

  • A project scaffold with a standards-compliant pyproject.toml
  • A resolver that produces a cross-platform lockfile, uv.lock
  • Automatic environment creation — you never activate a venv again
  • Interpreter downloads: it fetches Python 3.12 for you if you do not have it
  • A global tool installer, so linters and CLIs do not pollute project environments
  • A drop-in pip interface (uv pip) for migrating existing work gradually

uv.lock — why it is the important file

Exact versions

Every direct and transitive dependency, pinned, with hashes for integrity verification.

Cross-platform

One lockfile covers Linux, macOS and Windows. Not one lockfile per machine, as pip freeze produces.

Commit it

uv.lock belongs in git for applications and services. Libraries usually do not commit it.

The lockfile is what makes your deployment identical to your laptop. Without it you have a suggestion, not a build.

Unions, optionals and modern syntax

# modern (3.10+)
def find(id: str) -> Document | None: ...
score: int | float

# legacy equivalents — still seen in older code
from typing import Optional, Union
def find(id: str) -> Optional[Document]: ...

Optional[X] means X | None. It does not mean "this argument may be omitted" — that is a default value, a separate idea.

Pydantic: annotations that actually run

Pydantic reads your type hints and generates a validator in Rust that enforces them at runtime.

Parse

Take untrusted input — JSON, form data, an env var, a model response — and produce a typed object or a precise error.

Validate

Enforce constraints beyond the type: ranges, lengths, patterns, cross-field rules.

Serialize

Turn the object back into JSON or a dict, with control over aliases, exclusions and formats.

v2 rewrote the core in Rust — roughly five to fifty times faster than v1, which is why it can sit on every request.

Custom validators

from pydantic import field_validator, model_validator

class Query(BaseModel):
text: str
start: int
end: int

@field_validator("text")
@classmethod
def strip_it(cls, v: str) -> str:
return v.strip()

@model_validator(mode="after")
def check_range(self):
if self.end <= self.start:
raise ValueError("end must exceed start")
return self

field_validator sees one field. model_validator(mode="after") sees the whole validated object and is where cross-field rules belong.

asyncio

Concurrency for work that waits. Every AI service is a waiting machine — this module is what makes it fast.

docs.python.org/3/library/asyncio.html

Why async, in numbers

A RAG request: embed the query (120 ms), search three collections (80 ms each), call the model (2400 ms).

Synchronous

2760 ms

Every wait is serial. The CPU is idle for 99 percent of it.

Concurrent searches

2600 ms

The three searches overlap.

Under load

50x throughput

One process serves hundreds of waiting requests instead of one at a time.

Async does not make a single call faster. It stops one slow call from blocking every other user.

Module 3 — asyncio

The third card is the real argument — it is about concurrency capacity, not latency.

The mental model

Threads

The operating system interrupts your code anywhere. You need locks. Preemptive.

asyncio

Your code yields control only at an await. Between awaits nothing else runs. Cooperative.

Processes

True parallel CPU work, separate memory, expensive to start and to communicate with.

Cooperative scheduling is why async code needs far fewer locks — and why one badly-behaved function that never yields freezes the entire server.

Rule: asyncio for I/O-bound work. Processes for CPU-bound work. Threads mostly for wrapping blocking libraries you cannot change.

Module 3 — asyncio

The freeze risk on the middle card is the theme of the failure-mode slides later in this module.

The event loop

  1. The loop holds a queue of ready tasks
  2. It runs one until that task hits an await on something unfinished
  3. The task is parked; the loop picks the next ready one
  4. When the operating system reports the I/O is done, the task becomes ready again

One thread, one loop, thousands of parked tasks. The loop is only ever blocked by code that does not await.

You almost never touch the loop directly. asyncio.run creates it, runs your entry coroutine and shuts it down cleanly.

Coroutines: async def and await

import asyncio

Calling an async function returns a coroutine object. It does nothing until awaited or scheduled as a task.

A forgotten await is the classic beginner bug: you get a coroutine object where you expected data, plus a "never awaited" warning.

Two kinds of testing you need

Deterministic tests

Does the chunker split correctly? Does the retriever apply the filter? Does the endpoint return 422 on bad input? Same input, same answer, every time. Ordinary unit tests.

Evaluation

Is the answer faithful to the retrieved context? Did retrieval find the right document? Scored, not asserted. Compared across versions rather than passed or failed.

Most people building AI systems do neither. Doing both is the clearest possible evidence of seniority — and it is what lets you say "this change improved recall from 0.71 to 0.84" instead of "it seems better".

term-missing prints the exact uncovered line numbers, which is the only part of a coverage report anyone should act on.
