Folio3 · Topic 01 · Definition

What custom AI agent development is

Purpose-built systems that understand business objectives, access trusted company knowledge, use approved tools and complete defined workflows.

Unlike generic assistants, custom agents interact with internal systems, manage multi-step tasks, handle exceptions, request approvals and operate within documented security and governance boundaries.

Folio3 builds them around a client's workflows, data, approvals and systems, and suggests starting with a 2 to 4 week proof of concept.

The custom agent engine

Business-specific task execution

Trusted enterprise knowledge access

CRM, ERP, database and API integration

Human approval and escalation controls

Real-time monitoring and audit logging

Guardian-ready governance when enterprise oversight is required.

Your path · Topic 01 · How to achieve it

Building the foundations

How to achieve it

1

Pick one workflow with a clear owner, a measurable baseline and real exceptions, not a general assistant.

2

Write the agent's contract first: goal, allowed tools, readable data, actions needing approval, stop conditions.

3

Build the loop yourself once: model call, tool call, observation, repeat, with a step limit and a cost limit.

4

Add state, retrieval and human approval only when the bare loop shows it needs them.

Study plan

Read. Anthropic's "Building Effective Agents" and the ReAct paper (Yao et al., 2022), to tell workflows from agents.

Build. A small tool-calling agent in plain Python against one API, with no framework, then port it to LangGraph.

Prove. Run 20 real tasks; record completion rate, steps and cost per task, and explain every failure.

Your path · Topic 02 · How to achieve it

Measuring what an agent really does

How to achieve it

1

Define each metric before building: what counts as straight-through, first-pass and resolved, and who labels it.

2

Capture a baseline from the current manual process, or the percentages have nothing to be compared against.

3

Assemble a golden set of 50 to 200 real cases with expected outcomes, including the awkward exceptions.

4

Score retrieval separately from the final answer, so you know which half is failing.

Study plan

Read. The RAGAS metric definitions (context precision, faithfulness) and Hamel Husain's essays on LLM evals.

Build. An evaluation harness in LangSmith or Langfuse that replays the golden set on every change.

Prove. A one-page scorecard: baseline, current rate and sample size for each of the four metrics.

Your path · Topic 03 · How to achieve it

Choosing the right level of automation

How to achieve it

1

Start from the process, not the technology: stable, structured inputs point to RPA or plain code.

2

Use a chatbot or packaged tool when the task ends at an answer and no system has to change.

3

Justify a custom agent only where judgement, several systems and exceptions meet in one workflow.

4

Combine them: deterministic steps in code, and the model only at the decision points that need it.

Study plan

Read. The workflow patterns in "Building Effective Agents": chaining, routing, orchestrator and workers.

Build. The same invoice-matching task three ways: a script, a single prompt and a tool-using agent.

Prove. A decision matrix scoring the three on accuracy, cost per case, build effort and maintenance.

Your path · Topic 04 · How to achieve it

Delivering the six services yourself

How to achieve it

1

Discovery: interview the people doing the work, map the workflow and price each delay before proposing anything.

2

Architecture: draw the layers (model, memory, tools, controls, monitoring) and log each choice as a decision record.

3

Integration: wrap each system as one well-described tool; add a second agent only for a separable role.

4

Test, deploy, optimize: red-team before launch, release behind approvals, then review traces weekly.

Study plan

Read. Chip Huyen's "AI Engineering" for the full lifecycle, plus the Model Context Protocol specification.

Build. One service end to end, from discovery notes to a monitored deployment, for a process you know well.

Prove. A client-style portfolio: roadmap, architecture diagram, test report and a 30-day metrics review.

Folio3 · Topic 05 · Failure modes

Why most projects never reach production

Teams chase impressive demonstrations over ownership, integration, governance and measurable outcomes.

The POC trap

A promising proof of concept impresses stakeholders but lacks the ownership, controls, integration architecture, deployment plan and investment case production needs.

The generic agent ceiling

Off-the-shelf agents support simple tasks but struggle with the specific workflows, approvals, business rules, data sources and exceptions that drive operations.

Integration failure

An agent creates limited value when it cannot securely retrieve information, update records, trigger workflows or complete actions across existing systems.

The compliance blind spot

Agents without access controls, decision boundaries, human approvals, audit trails and clear accountability create operational, financial, legal and reputational risk.

Your path · Topic 06 · How to achieve it

Running the process on a real workflow

How to achieve it

1

Map the workflow as a swimlane diagram with times, volumes and exception rates at each step.

Turn the map into a tool list and a risk list; every risky action gets an approval or a hard limit.

Your path · Topic 07 · How to achieve it

Engineering each component

How to achieve it

1

Reasoning: choose the smallest model that passes your evals; keep prompts versioned and tested like code.

2

Memory and RAG: separate short-term state from long-term knowledge; tune chunking and reranking with retrieval metrics.

3

Planning and tools: give each tool a typed schema, a clear description and a safe failure message; cap steps and retries.

4

Governance and monitoring: enforce permissions outside the model, and trace every call from the first day.

Study plan

Read. The Reflexion and Plan-and-Solve papers, and the OpenTelemetry GenAI semantic conventions for tracing.

Build. A LangGraph agent with a checkpointer, a reranked retriever, three typed tools and an approval interrupt.

Prove. An ablation table showing what each component adds to task success, latency and cost.

Your path · Topic 08 · How to achieve it

Scoping and pricing agent work

How to achieve it

1

Scope by workflow, not by hours: one workflow, its systems, its exception paths and its success metric.

2

Estimate running cost from tokens per task times volume, then add retries, evaluation runs and monitoring.

3

Price the proof of concept as a small fixed commitment with a clear exit; it buys information, not software.

4

Put assumptions about data readiness and system access in writing; they cause most overruns.

Study plan

Read. Model pricing and prompt-caching documentation, and Folio3's article on enterprise AI implementation cost.

Build. A spreadsheet cost model: tokens, calls, volume, human review time and infrastructure per month.

Prove. A two-page POC proposal with scope, timeline, cost range, risks and go or no-go criteria.

Your path · Topic 09 · How to achieve it

Learning a domain well enough to build

How to achieve it

1

Choose one or two industries and learn their workflows, vocabulary, records and regulators before any code.

2

Look for the document-heavy, rule-bound, high-volume task; that is where agents pay back first.

3

Learn the domain's system of record and its interface: FHIR in healthcare, core banking APIs, an ERP.

4

Keep the licensed professional as the final decision-maker, and design the agent around their review.

Study plan

Read. One domain standard in depth, such as HL7 FHIR, or your banking regulator's guidance on AI and outsourcing.

Build. A domain agent on public or synthetic data, such as a contract clause extractor or an invoice matcher.

Prove. Ask a practitioner from that field to review 30 outputs, and record what they would change.

Governance and compliance in every agent

Built into access, data use, approvals, tool permissions, testing and monitoring from the beginning.

Human-in-the-loop safeguards

Route uncertain, sensitive, high-value or policy-defined decisions to authorized employees before consequential actions are completed.

Permission-aware tools

Your path · Topic 10 · How to achieve it

Making governance real

How to achieve it

1

Classify every tool action by risk: read-only, reversible write, irreversible or financial. Approvals follow the class.

2

Enforce permissions in the tool layer with the user's own identity, never by asking the model to behave.

3

Log each run as a trace: prompt, retrieved context, tool calls, approvals and outcome, with retention rules.

4

Red-team before launch for prompt injection, data leakage and excessive agency, and again after each change.

Study plan

Read. The OWASP Top 10 for LLM Applications, the NIST AI RMF with its Generative AI Profile, and ISO/IEC 42001.

Build. An approval interrupt and role-based tool access in LangGraph, then attack it with garak, PyRIT or promptfoo.

Prove. A risk register and a red-team report listing each attack, its result and the fix.

Your path · Topic 11 · How to achieve it

Getting fluent in the stack

How to achieve it

1

Go deep on one tool per layer and stay literate in the rest; breadth without depth does not ship.

2

Hide the model behind a thin interface so providers can be swapped and compared on your own evals.

3

Pick the orchestrator by need: LangGraph for stateful control, CrewAI or AutoGen for role-based teams, n8n for low-code flows.

4

Containerize early; an agent that only runs in a notebook has not been integrated with anything.

Study plan

Read. The LangGraph, CrewAI and AutoGen quick-starts side by side, plus one vector database's indexing and filtering guide.

Build. The same agent in two orchestrators, on Chroma locally and Pinecone or Weaviate hosted, shipped in Docker.

Prove. Deploy it to one cloud with an authenticated endpoint, managed secrets and a load test.

Your path · Topic 12 · How to achieve it

Building a prior authorization agent

How to achieve it

1

Learn the workflow: request, clinical documentation, payer rules, decision, appeal, and where each delay occurs.

2

Split the work: extraction and document checks for the agent, medical-necessity judgement for clinicians.

3

Integrate through standards where they exist, such as FHIR and X12 278, instead of scraping payer portals.

4

Treat patient data as regulated from the first prototype: synthetic test data, access logs, minimum necessary access.

Study plan

Read. The CMS prior authorization rule (CMS-0057-F), the Da Vinci PAS implementation guide and a HIPAA Security Rule summary.

Build. A prototype on Synthea synthetic patients that assembles a request packet and flags missing documents.

Prove. Compare turnaround and missing-document rate with a manual baseline on 50 synthetic cases.

Folio3 · Topic 14 · FAQs

Questions the page answers

Agent or chatbot?

A chatbot answers questions. An agent retrieves information, uses tools, updates systems and completes multi-step workflows.

How long does it take?

From a two-to-four-week validation sprint to a multi-month enterprise rollout, depending on scope and readiness.

Will it fit our systems?

Yes: CRM, ERP, finance applications, databases, APIs, legacy systems and internal tools, through secure integrations.

What stops rogue actions?

Role-based permissions, action limits, approval checkpoints, audit logging, red-teaming and human escalation.

How is ROI measured?

Against documented baselines: processing time, cost per task, intervention rate, throughput and error rate.

What should we prepare?

One high-value workflow, the systems and data it touches, who approves risky actions, and how success is measured.
